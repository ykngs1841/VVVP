# Day 1 메모 — 요구사항 + 구조 스케치
(정식 문서 아님. 코딩 시작 전 방향만 확인하는 용도. README에 들어갈 "선택" 근거의 원재료.)

## 1. 이번 주에 만들 것 (한 문장)
운전자가 START를 누르면 실제 차량처럼 ECU → Battery → StarterMotor → Engine → Alternator → Dashboard 순서로 상태가 전파되는 콘솔 시뮬레이터. 안전 인터록 3개, 가속/감속/기어변경, 고장 1개(배터리 부족)까지만.

## 2. 문제 / 제약 (README에 그대로 쓸 문장 초안)
- **문제**: 값만 증가시키는 장난감이 아니라, 실제 차량의 시동 시퀀스·안전 인터록 구조를 이해하고 객체지향으로 모델링하고 싶었다.
- **제약**: 1주일, C++ 기초 수준(직전 프로젝트는 Blackjack — main.cpp에 로직이 몰려있고 new/delete 관리가 안 됨). → 이번엔 계층 분리 + 메모리 관리를 처음으로 제대로 해본다.

## 3. 핵심 흐름 (손그림 수준 ASCII)
```
운전자 → Vehicle
           ├─ ECU가 시동 시퀀스 지휘
           │   └─ FaultManager에게 "지금 시동 걸어도 돼?" 확인
           │        (브레이크 눌렀는지 / 기어 P,N인지 / 배터리 전압 충분한지)
           ├─ 통과하면 Battery → StarterMotor → Engine → Alternator 순서로 상태 갱신
           └─ 결과를 Dashboard가 화면에 출력
```

## 4. 클래스 후보 (딱 한 줄씩만)
- `Vehicle` — 모든 부품을 소유하고 운전자 명령을 전달만 함
- `ECU` — 시동 시퀀스 지휘
- `FaultManager` — 안전조건 판정 + 배터리부족 고장 판정 (제어 권한 없음, 읽기만)
- `Battery` / `StarterMotor` / `Engine` / `Alternator` / `Transmission` — 각자 상태 하나씩만 관리
- `Dashboard` — 상태값 받아서 출력만

## 5. 지키기로 한 규칙 (블랙잭에서 안 했던 것)
- `main.cpp`는 `Vehicle`만 안다 (하위 부품 직접 호출 금지)
- 부품끼리는 서로 모른다 — 조율은 `ECU`/`Vehicle`을 통해서만
- 헤더(.h)에 `using namespace std` 안 씀
- `new` 쓰면 반드시 짝이 되는 `delete` 확인
